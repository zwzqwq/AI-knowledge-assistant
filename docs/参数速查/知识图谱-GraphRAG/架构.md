# 知识图谱-GraphRAG —— 架构

> 功能目标：**为"概念间关系"类问答提供结构化语义——向量检索找"相似"文本，知识图谱找"相关"实体（A 和 B 什么关系、哪些引擎支持事务）。**
> 功能位置：文档入库（`chat_service.add_document`）→ LLM 实体抽取（`extractor`）→ NetworkX 存储（`graph_store`）→ 提问时 `graph_query_node` 查询 → ToolMessage → generate。
> 原理详解见 `Notes/LangChain/01-RAG-从零理解.md`、`03-Chroma向量库内部结构.md`（通用概念不重复展开），本页只讲"代码怎么组织的、文件怎么分工"。

## 一、链路全景

```
[用户上传文档]
  ▼
chat_service.add_document(content, filename)        ← 入口（chat_service.py:65）
  ├─ 切片入库（向量库——RAG 功能的事，不在本链）
  └─ filename 首次上传？→ _build_knowledge_graph(chunks, filename)   （chat_service.py:99）
        ▼
     KnowledgeExtractor.extract(text)               ← LLM 抽三元组（extractor.py:54）
        ▼
     GraphStore.add_triples(triples)                ← NetworkX + JSON 持久化（graph_store.py:64）
        ▼
     data/knowledge_graph.json                      ← 落盘

[用户提问·关系型问题]
  ▼
router 决策调 graph_query（prompts.py 决策规则）
  ▼
graph_query_node（nodes.py:285）
  ▼
GraphStore().query_to_text(entity)                  ← 双向查找+模糊匹配（graph_store.py:155）
  ▼
ToolMessage → generate 组织回答

[删除文档·旁支]
  ▼
chat_service.delete_document → 图谱无法按文档回滚（graph_affected=False）
  ▼
指纹集合同样不回滚 → 重传相同内容不重复抽取（图谱残留旧三元组）
```

## 二、文件职责（按链路顺序）

| 编号 | 文件 | 职责 | 一句话 |
|------|------|------|--------|
| 01 | `src/services/chat_service.py` | 编排触发 | `add_document` 按**内容指纹**（MD5）首次建图防重复抽取；`delete_document` 旁支 |
| 02 | `src/kg/extractor.py` | 实体关系抽取 | LLM 从 chunk 抽三元组，严格 JSON 输出 + 容错解析 |
| 03 | `src/kg/graph_store.py` | 图谱存储+查询 | NetworkX 有向图，count/weight 加权，JSON 持久化，单例 |
| 04 | `src/agent/tools.py` | 工具声明 | graph_query 签名（entity 参数）给 LLM 的 function calling 看 |
| 05 | `src/agent/prompts.py` | 决策规则 | router 首次必查图谱、对比型检查双方覆盖 |
| 06 | `src/agent/nodes.py` | 工具执行 | graph_query_node 找未执行调用 → `query_to_text` → ToolMessage |
| 07 | `src/config.py` | 参数中心 | LLM_* 参数（extractor 的 ChatOpenAI 消费） |

## 三、数据流（谁调用谁）

```
chat_service.add_document(content, filename)
  → _build_knowledge_graph(chunks, filename)          # 仅 filename 首次入库时
      → extractor.extract(text)                        # 每 chunk（len≥20）
          → GraphStore().add_triples(triples)          # 单例，内部 _save()
              → data/knowledge_graph.json              # JSON 落盘
router（读 prompts.py 决策规则）→ graph_query_node
  → GraphStore().query_to_text(entity)                 # 单例，内存图
      → ToolMessage(content=图谱查询结果文本)
          → generate 组织最终回答
delete_document(filename)
  → 指纹集合不回滚（图谱无法按文档回滚，重传同内容不重复抽）
```

**接口稳定原则**：新增文件（kg/extractor.py、kg/graph_store.py）对既有代码零侵入——`chat_service` 内部调用，对外 API 不变；`graph_query_node` 复用既有工具循环（`_find_pending_tool_call`），不新增路由逻辑。

## 四、关键设计决策

1. **抽取时机 = 文档入库时一次性，不是提问时**：LLM 实体抽取慢且费钱，放提问路径每次都要等；放入库路径，一次抽取终身复用。配套**内容指纹集合**（MD5 of content）：指纹相同 ⇔ 内容完全相同，只建一次图——比原"文件名防重"更强，能挡"改名重传"（内容相同但文件名不同的文档不会重复抽取）。部分重复（内容更新）指纹不同 → 正常重抽（新信息）。【推断】证据：`chat_service.py` 注释 + 本次指纹优化。
2. **建图失败不阻塞文档入库**：`_build_knowledge_graph` 整个包在 `try/except` 里（`chat_service.py:124`），异常只记 warning——图谱是增强能力，向量库才是主路径，挂了图谱不影响文档入库和检索。
3. **NetworkX 有向图 + count/weight 加权**：关系有方向（A 支持 B ≠ B 支持 A）所以 DiGraph；节点 count = 出现次数（越重要）、边 weight = 重复出现叠加——查询时按权重排序，把"反复提到的关系"排前面。轻量内存图 + JSON 持久化，不用图数据库（Neo4j）——数据量级（几百实体）用图数据库是杀鸡用牛刀。【推断】证据：`graph_store.py:1-16` 模块注释 + `add_triples` 的 count/weight 逻辑。
4. **单例模式 + 延迟导入 networkx**：`__new__` 保证全进程一个 GraphStore 实例（图谱只加载一次）；networkx 延迟导入避免 Streamlit 启动时潜在导入错误（`graph_store.py:22-23` 注释）。
5. **查询容错**：实体不存在时**模糊匹配**（包含匹配取 count 最高的，`graph_store.py:113-117`）——LLM 抽的实体名和用户问法不完全一致时仍能命中。
6. **图谱无法按文档回滚**：NetworkX 图不记录三元组来源文件，删除文档只能清向量库切片，图谱残留（`chat_service.py` 注释明示）。设计权衡：接受"删除不彻底"，换取存储简单；指纹集合也不回滚（图谱残留旧三元组，重传相同内容不应重复抽取）。

## 五、依赖清单

| 依赖 | 用途 | 为什么选它 |
|------|------|-----------|
| `langchain-openai`（ChatOpenAI） | 实体抽取 LLM | 复用现有 DeepSeek 通道，不新增模型 |
| `networkx` | 内存图结构（DiGraph） | 轻量、纯 Python、支持节点/边属性；量级小无需图数据库 |
| `json` + `os`（标准库） | 图谱持久化 | 单文件 JSON，简单可靠 |

## 六、降级策略（面试加分）

| 故障点 | 兜底方案 | 位置 |
|--------|---------|------|
| LLM 抽取失败（网络/限流） | `except` 返回 `[]`，该 chunk 跳过，不中断整个建图 | extractor.py:76-78 |
| LLM 返回 JSON 解析失败 | `_parse_json` 容错：清理代码块 → 正则提取第一个 JSON 对象 → 仍失败返回 `[]` | extractor.py:100-121 |
| 图谱 JSON 加载失败 | 从空图开始（`_load` 的 except 重建空 DiGraph） | graph_store.py:221-224 |
| 查询实体不存在 | 模糊匹配 → 仍无 → 占位"（知识图谱中未找到…）" → 来源判定排除 → 走 web_search/LLM 兜底 | graph_store.py:158-159 |
| 建图整体失败 | `chat_service` try/except 只记 warning，文档照常入库 | chat_service.py:124-125 |
