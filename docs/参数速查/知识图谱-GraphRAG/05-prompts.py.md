## 核心方法

### 图谱相关决策规则（`prompts.py:3-24` 提取）

```
① 首次收到用户消息 → 必须调 retrieve + graph_query，不输出文字
   （图谱和知识库是"双查"——关系型问题只有图谱能答）
② 收到检索结果后判断相关性：
   - 用户问的是对比或配对（A vs B）→ 检查检索结果是否同时覆盖双方
     - 只覆盖一方 → 调 web_search 补缺失方
     - 双方都覆盖 → generate
③ 重试纪律（同工具最多重试 2 次，重试必改查询参数）
```

> **设计要点**
> - **"首次必调 graph_query"是图谱的保底曝光**：即使问题是普通知识型，图谱也可能提供关系线索——所以和 retrieve 绑定为首次必查组合。【推断】证据：`prompts.py:11` 决策规则 1。
> - **对比型问题的图谱作用**：判断"检索结果是否同时覆盖双方"时，图谱的关系边可以快速确认双方是否存在——缺一方才触发 web_search，避免盲目联网。
> - 图谱的"兜底链位置"：知识库（retrieve）→ 图谱（graph_query）→ 联网（web_search），三者从本地到外部递进。
