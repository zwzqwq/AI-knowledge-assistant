# 对话问答 —— 架构

> 功能目标：**用户输入一个问题，经过"决策 → 检索 → 再决策 → 生成"的 Agent 循环，最终把完整回答逐字流式返回（打字机效果）。**
> 功能位置：`src/ui/app.py`（或 curl）→ `POST /chat/stream` → `chat_service.stream_chat` → LangGraph（summarize → router → 工具循环 → generate）→ SSE 逐字输出。
> 原理详解见 [Notes/AI-Agent/AI-Agent核心概念-小林.md](../../../../Notes/AI-Agent/AI-Agent核心概念-小林.md)、[Notes/LangChain/langchain-agent-learning.md](../../../../Notes/LangChain/langchain-agent-learning.md)、[Notes/Python/12_异步编程.md](../../../../Notes/Python/12_异步编程.md)（通用概念不在此重复展开），本页只讲"代码怎么组织的、文件怎么分工"。

## 一、链路全景

```
[用户] 输入问题
  │
  ▼
src/ui/app.py (Streamlit, 纯 HTTP 客户端) ──httpx──► 或 curl 直接调
                                                        │
                                                        ▼
            POST /chat/stream   ◄── src/api/server.py:60 chat_stream
            ChatRequest 校验        (src/api/schemas.py:19)
            StreamingResponse(SSE)  ← 包成 text/event-stream
                                                        │
                                                        ▼
            src/services/chat_service.py:163  stream_chat(message, session_id)
                ① _get_or_create_history(session_id)     → src/memory/history.py
                ② history.add_user(message)
                ③ retriever = get_hybrid_retriever()      → src/rag/retriever.py → src/rag/ensemble.py
                ④ agent = build_agent_graph(retriever)    → src/agent/graph.py
                ⑤ 追问上下文注入 → initial_state
                ⑥ async for chunk in agent.astream(initial_state)  ← 逐节点跑图
                ⑦ 判定回答来源 → yield "source" 事件
                ⑧ 逐字 yield "token" 事件
                ⑨ history.add_assistant(final_answer) ; yield "done"
                                                        │
                                                        ▼
[浏览器] 逐字显示回答

═══ 图内循环（一次提问）═══
graph.py 编译 StateGraph(AgentState)：
  summarize ──add_edge──► router ──route_after_router──┬─有tool_calls→ pick_next_tool ──分发──► retrieve / web_search / graph_query
      ▲                                                 │                                          │
      │                                                 └─无tool_calls→ generate ──END              │ should_continue
      │  ◄──────────(当前轮工具全执行完 → 回 router 再决策)◄─────────────────────────────────────────┘
```

**一次提问 = 多次 LLM 调用**：router 每被回一次就调一次（决策），最后 generate 调一次（生成）。举例：提问 → router 决定查知识库+图谱 → 执行两个工具 → 回 router 判断结果相关性 → 相关则 generate；若 router 觉得结果不相关，会再调 web_search，直到无工具可调或迭代到 12 次上限。

## 三、数据流（谁调用谁）

```
用户 ──► src/ui/app.py
           │  httpx POST http://127.0.0.1:8000/chat/stream
           ▼
src/api/server.py chat_stream
           │  StreamingResponse(chat_service.stream_chat(...))
           ▼
src/services/chat_service.py stream_chat
   ├─► src/memory/history.py  add_user / add_assistant / messages
   ├─► src/rag/retriever.py   get_hybrid_retriever()
   │      └─► src/rag/ensemble.py HybridRetriever(vector, bm25, reranker)
   ├─► src/agent/graph.py     build_agent_graph(retriever)
   │      ├─► src/agent/state.py  AgentState
   │      ├─► src/agent/nodes.py  节点函数（绑 retriever / llm）
   │      ├─► src/agent/edges.py  条件边函数
   │      └─► src/agent/tools.py  TOOLS（bind_tools）
   │            └─► src/agent/prompts.py  ROUTER_SYSTEM_PROMPT
   └─► agent.astream(initial_state)  → 逐节点执行 → 返回 final_answer
              ▲
              │ nodes.py: retrieve_node ──► retriever.invoke(query)（HybridRetriever）
              │          web_search_node ──► src/agent/web_search.py search_bing()
              │          graph_query_node ──► src/kg/graph_store.py GraphStore()
              └──────────────┘
   → source 事件 → token 逐字 → done → (server.py SSE 流回前端)
```

**接口稳定原则**：对外唯一接口是 `POST /chat/stream`（请求 `{message, session_id}`，响应 SSE 事件 `source/token/done/error`）。UI 从直接 import ChatService（Phase 4 之前）改成纯 HTTP 客户端后，前端可以换成任意技术栈（React/Vue）而后端零改动。【推断】证据：`src/ui/app.py:4-12` 注释明确写了 Phase 4 的前后端分离决策。

## 四、关键设计决策

1. **编排与图分离**：`chat_service` 管"会话历史 + SSE 事件 + 组装检索器"，`graph.py` 只管"决策循环怎么走"。好处：① 前端可换；② 同一个图可被别处复用；③ 单元测试能分别测 graph 和 service。【推断】证据：`chat_service.py:1-22` 文档字符串说明从 UI 抽离业务逻辑的动机。

2. **一次提问 = 多次 LLM 调用，决策与生成用不同温度**：router 用 `temperature=0`（决策要确定性，`nodes.py:35` `_make_router_llm`）、max_tokens=512；generate 用 `temperature=0.7`（回答要自然，`nodes.py:23` `_make_llm`）。备选方案是"一次 LLM 调用内嵌工具"，但那样无法自主决定调几个工具、顺序如何。

3. **工具声明与执行分离**：`tools.py` 的 `@tool` 只产出 JSON Schema（给 LLM 的 function calling 协议看签名），**真正执行在 nodes.py 的工具节点**里（`_find_pending_tool_call` 找未执行的 tool_call → 执行 → 返回 ToolMessage）。这是手动管理工具循环，不用 LangChain `ToolNode`——好处是对"执行哪个、执行几次、结果怎么放回"有完全控制权。【推断】证据：`tools.py:27-29` 注释"实际实现由 nodes.py 完成"。

4. **历史管理双轨**：
   - **外层** `ConversationHistory`（`history.py`）：session 级内存 dict，存每轮 user/assistant 原文，作用 = 拼"追问上下文"（`chat_service.py:183`）。
   - **内层** LangGraph `state["messages"]` + `conversation_summary`：图内窗口管理，旧纯对话压缩成摘要（`nodes.py:122`）。
   - 两者各管各的、互不替代——外层是"跨请求的会话记忆"，内层是"单次图执行的消息窗口"。

5. **追问上下文注入**（`chat_service.py:183-202`）：图内的 router 每次只看到"当前一轮"的消息（`_build_router_messages` 只保留当前轮+最近8条纯对话），跨轮信息靠编排器把"上轮问题+上轮回答+当前追问"拼成一句话塞进 initial_state。备选是直接把多轮历史全塞进图，但那样窗口管理会失控、Token 膨胀。

6. **迭代安全阀**：`MAX_ITERATIONS = 12`（`edges.py:6`），router 每轮递增 iteration，超过强制进 generate——防止"决策模型反复调工具"的死循环。

## 五、依赖清单

| 依赖 | 用途 | 为什么选它 |
|------|------|-----------|
| `fastapi` + `uvicorn` | HTTP 服务 + SSE 流式响应 | 原生支持 `StreamingResponse(text/event-stream)`，Pydantic 自动校验 |
| `streamlit` + `httpx` | Web 前端（纯客户端） | 最快出界面，`httpx` 支持异步流式消费 SSE |
| `langgraph` | 状态机（StateGraph / add_messages） | 官方支持消息追加 reducer、条件边、astream |
| `langchain-openai` | `ChatOpenAI` 调 DeepSeek（OpenAI 兼容） | 一行绑定，`bind_tools` 支持 function calling |
| `langchain-core` | `Document` / `BaseRetriever` / `@tool` / messages | RAG 与 Agent 的公共类型底座 |
| `sentence-transformers` | embedding（bge-small-zh）+ Rerank（bge-reranker-base） | 中文效果好、本地推理免 API |
| `chromadb` | 向量库持久化 | 轻量、单文件目录、支持按 id 删除（清理脏数据） |
| `rank_bm25` + `jieba` | BM25 召回 + 中文分词 | BM25 补全向量检索的精确关键词匹配 |
| `requests` | Bing 搜索（抓 HTML 正则解析） | 零 API key、零成本联网兜底 |

## 六、降级策略（面试加分）

| 故障点 | 兜底方案 | 位置 |
|--------|---------|------|
| LLM 调用失败（认证/限流/超时/网络） | 分类捕获 → 返回 SSE `error` 事件 | `chat_service.py:269-291` |
| 知识库检索无结果 | `retrieve` 返回占位"（知识库中未找到相关内容）"→ router 按规则改调 web_search | `nodes.py:260` |
| Bing 搜索失败/无结果 | `search_bing` 返回 `[]` → 占位"（联网搜索未找到相关内容）" | `web_search.py:36,83` |
| 所有工具都没结果 | sources 判定落 `llm` → generate 用模型自身知识回答 | `chat_service.py:257` |
| 决策循环失控 | `MAX_ITERATIONS=12` 强制进 generate | `edges.py:6` |
| Agent 未返回结果（bug 兜底） | 返回 SSE `error` 事件 | `chat_service.py:232` |
